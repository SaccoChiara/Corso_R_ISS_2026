Modulo 09 - Report automatici con Quarto

Obiettivi del modulo

  • Creare un documento Quarto e trasformarlo in un report Word con il pulsante Render
  • Modificare l’intestazione YAML per impostare titolo, autore, data e opzioni del documento
  • Inserire blocchi di codice (chunk) e controllarne il comportamento con le opzioni #|
  • Scrivere il testo del report con la sintassi Markdown e inserire numeri calcolati da R direttamente nel testo

Iniziamo!

Nei giorni scorsi hai pulito i dati della coorte vaccinale, hai creato tabelle e grafici. Ma immagina di dover preparare lo stesso report ogni mese, con i dati aggiornati: dovresti rieseguire lo script, copiare ogni tabella e ogni grafico in Word, aggiornare a mano i numeri nel testo… e sperare di non sbagliare nulla.

Quarto risolve questo problema: in un unico documento scrivi il testo del report e il codice R che produce tabelle, grafici e numeri. Con un clic, Quarto esegue il codice e crea il report finale (in Word, HTML, PDF o altri formati). Quando arrivano dati nuovi, basta rifare il clic.

In questo modulo creerai un report in Word sulla coorte vaccinale.

ConsiglioApprofondimento: Quarto e R Markdown

Forse hai già sentito parlare di R Markdown (file .Rmd): è lo strumento “storico” per fare report con R, e funziona in modo molto simile. Quarto (file .qmd) ne è l’evoluzione: la sintassi è quasi la stessa, ma funziona anche con altri linguaggi (Python, Julia) ed è già installato insieme a RStudio. Anche le esercitazioni di questo corso sono scritte in Quarto!

Creare un documento Quarto

Il nuovo documento

In RStudio clicca su File -> New File -> Quarto Document…. Nella finestra che si apre:

  • scrivi un titolo provvisorio in Title e il tuo nome in Author (potrai cambiarli dopo);
  • in Format scegli Word;
  • lascia Engine su Knitr, il motore che esegue il codice R;
  • togli la spunta da Use visual markdown editor: per imparare conviene vedere il testo “così com’è”;
  • clicca su Create.

Si apre un nuovo documento con un contenuto di esempio. Salvalo subito con File -> Save nella sottocartella script con il nome report_coorte.

Com’è fatto un documento Quarto

Guarda il documento di esempio: contiene tre tipi di elementi.

  1. In cima, tra due righe di tre trattini (---), c’è l’intestazione YAML, con le informazioni generali del documento (titolo, autore, formato).
  2. Ci sono dei blocchi di codice (in inglese chunk), su sfondo grigio, che iniziano con ```{r} e finiscono con ```. Contengono codice R, esattamente come uno script.
  3. Tutto il resto è testo, scritto con una sintassi semplice chiamata Markdown.

Li vedremo uno alla volta.

Il render

Il primo report

Per trasformare il documento in un report, clicca sul pulsante Render (con la freccia blu) in alto, oppure usa la combinazione di tasti Ctrl + Shift + K (Cmd + Shift + K su Mac).

Nel riquadro in basso vedrai comparire il lavoro di Quarto. Se tutto va bene, si aprirà il file Word, che trovi anche nella stessa cartella del documento Quarto, con lo stesso nome (report_coorte.docx). Confronta il file Word con il documento Quarto: cosa è successo al codice e al testo?

Quarto fa le seguenti operazioni durante il render:

  1. esegue tutti i blocchi di codice, dall’alto verso il basso;
  2. mette insieme testo, codice e risultati (tabelle, grafici, numeri);
  3. crea il file nel formato richiesto.

Il file Word è un normale documento: puoi modificarlo, aggiungere commenti e inviarlo via email. È un formato comodo quando l’analisi è automatica, ma l’interpretazione dei risultati la scrivi tu.

AvvisoAttenzione al file Word aperto

Se il file Word è ancora aperto quando rifai il render, su Windows compare un errore e il report non viene aggiornato: Word “blocca” il file. Chiudi sempre il file Word prima di ogni nuovo render.

AvvisoAttenzione: il render parte da zero

Il render avviene in una sessione di R nuova e vuota: non vede gli oggetti che hai nel pannello Environment e i pacchetti che hai caricato nella console. Per questo il documento Quarto deve contenere tutto il codice necessario, dal caricamento dei pacchetti all’importazione dei dati. Se il render si ferma con un errore come object 'dati_clean' not found oppure could not find function, quasi sempre manca un passaggio nel documento.

ConsiglioApprofondimento: gli altri formati

Lo stesso documento può diventare un report in formati diversi: basta cambiare il formato nell’intestazione YAML (che vedremo tra poco).

  • html: una pagina web che si apre nel browser, anche senza internet: il file resta sul tuo computer. Permette elementi interattivi (schede, sommario cliccabile, codice nascosto).
  • pdf: richiede un programma aggiuntivo (TinyTeX), che si installa con il comando quarto install tinytex nel riquadro Terminal di RStudio. In alternativa puoi creare il Word e salvarlo in PDF.
  • pptx o revealjs: presentazioni (PowerPoint o HTML).

Puoi leggere di più nella guida ufficiale di Quarto (vedi le Risorse aggiuntive).

L’intestazione YAML

Titolo, autore e data

L’intestazione YAML (la sigla, un po’ scherzosamente, sta per YAML Ain’t Markup Language) è la parte in cima al documento, tra le due righe ---. Ogni riga contiene una chiave, seguita da due punti e dal suo valore:

---
title: "Untitled"
author: "Nome Cognome"
format: docx
editor: source
---

Modifica l’intestazione del tuo documento in modo che il report abbia:

  • il titolo “Report sulla coorte vaccinale”;
  • il sottotitolo “Vaccinazione e diagnosi di COVID-19, 2021” (chiave subtitle);
  • il tuo nome, o quello del tuo ufficio, come autore;
  • la data di oggi, che si aggiorna da sola a ogni render (chiave date, con il valore today);
  • la data scritta per esteso in italiano (chiavi date-format: long e lang: it).

Poi rifai il render e guarda il risultato.

Clicca per leggere un suggerimento


  • I testi vanno tra virgolette, today no: è una parola speciale che Quarto riconosce.
  • L’ordine delle chiavi non conta.
  • Senza lang: it la data viene scritta in inglese (es. “December 4, 2026”).


Clicca per vedere la soluzione (provaci da solo prima!)

AvvisoAttenzione agli spazi nello YAML

Lo YAML è molto pignolo: dopo i due punti ci vuole uno spazio (title: "Report", non title:"Report"), e quando una chiave contiene altre chiavi annidate queste vanno rientrate di due spazi (lo vedrai tra poco). Se il render si ferma con un errore che parla di YAML, controlla per prima cosa spazi e due punti.

Le opzioni del formato

Alcune chiavi riguardano solo un formato. In quel caso il formato non si scrive più sulla stessa riga (format: docx), ma diventa una chiave che contiene altre chiavi, rientrate di due spazi:

format:
  docx:
    toc: true
    number-sections: true
  • toc: true aggiunge un sommario (table of contents) all’inizio del documento;
  • number-sections: true numera i titoli delle sezioni.

Aggiungi le due opzioni al tuo documento e rifai il render.

Prova a rispondere!

I blocchi di codice

Inserire ed eseguire un chunk

Cancella tutto il contenuto di esempio sotto l’intestazione YAML (l’intestazione no!). Poi:

  1. scrivi una riga di testo, per esempio “Qualche semplice calcolo:”;
  2. vai a capo e inserisci un nuovo chunk con la combinazione di tasti Ctrl + Alt + I (Cmd + Option + I su Mac), oppure con il pulsante verde +C in alto;
  3. dentro il chunk scrivi:
2 + 2
10 / 5

Per eseguire il chunk mentre lavori, senza fare il render, clicca sulla freccia verde in alto a destra del chunk: il risultato compare sotto il chunk. Puoi anche eseguire una riga alla volta con Ctrl + Invio, come in uno script.

Ora rifai il render. Nel report Word vedi solo i risultati, o anche il codice?

Le opzioni dei chunk

Per impostazione predefinita il report mostra sia il codice sia il risultato. Per un report destinato ai colleghi o ai decisori di sanità pubblica, però, di solito il codice non serve. Il comportamento di ogni chunk si controlla con delle opzioni, scritte nelle prime righe del chunk e precedute da #|:

Le opzioni più utili sono elencate qui sotto; nel chunk, ricorda, ognuna va scritta su una riga a sé dopo #|.

Opzione Cosa fa
echo: false esegue il codice e mostra il risultato, ma nasconde il codice
eval: false mostra il codice ma non lo esegue
include: false esegue il codice ma non mostra nulla (né codice né risultato)
warning: false nasconde i warning
message: false nasconde i messaggi (per esempio quelli dei pacchetti)
fig-cap: "..." aggiunge una didascalia al grafico prodotto dal chunk
tbl-cap: "..." aggiunge una didascalia alla tabella prodotta dal chunk

Aggiungi #| echo: false al tuo chunk e rifai il render. Poi prova #| eval: false e #| include: false, e confronta i risultati.

Prova a rispondere!

Il chunk che carica i pacchetti deve essere eseguito, ma nel report non deve comparire nulla. Quale opzione usi?
ConsiglioApprofondimento: le opzioni in stile R Markdown

Nei documenti R Markdown, e in molti esempi che troverai online, le opzioni sono scritte dentro le parentesi graffe: ```{r, echo=FALSE}. Funziona anche in Quarto, ma lo stile con #| è quello consigliato: è più leggibile e usa true e false in minuscolo, come nello YAML.

Le opzioni per tutto il documento

Scrivere #| echo: false in ogni chunk è scomodo. Le opzioni che valgono per tutti i chunk si scrivono una volta sola nell’intestazione YAML, sotto la chiave execute:

execute:
  echo: false
  warning: false

Le opzioni scritte in un chunk hanno la precedenza su quelle generali: se un giorno vorrai mostrare il codice di un solo chunk, basterà scrivere #| echo: true in quel chunk.

Aggiungi all’intestazione YAML le opzioni execute qui sopra e, per nascondere anche i messaggi dei pacchetti, queste righe:

knitr:
  opts_chunk:
    message: false

Clicca per vedere la soluzione (provaci da solo prima!)

 


---
title: "Report sulla coorte vaccinale"
subtitle: "Vaccinazione e diagnosi di COVID-19, 2021"
author: "Nome Cognome (Istituto Superiore di Sanità)"
date: today
date-format: long
lang: it
format:
  docx:
    toc: true
    number-sections: true
execute:
  echo: false
  warning: false
knitr:
  opts_chunk:
    message: false
editor: source
---


AvvisoAttenzione a message: false

Hai notato che message: false non è sotto execute: insieme a echo e warning? Il motivo è che Quarto funziona anche con altri linguaggi (per esempio Python), e sotto execute: accetta solo le opzioni comuni a tutti. I messaggi (le scritte informative che R stampa, per esempio quando carichi un pacchetto) esistono solo in R: se scrivi message: false sotto execute:, Quarto lo ignora senza avvisarti e i messaggi compaiono comunque nel report.

Per le opzioni specifiche di R si usa knitr: opts_chunk:, che le passa direttamente a knitr, il pacchetto che esegue il codice R del documento. In alternativa, puoi scrivere #| message: false nel singolo chunk che produce i messaggi.

Il testo

La sintassi Markdown

Il testo del report si scrive con la sintassi Markdown: pochi simboli che indicano come formattare il testo.

Scrivi nel documento Nel report ottieni
# Titolo un titolo di primo livello
## Sottotitolo un titolo di secondo livello
**grassetto** grassetto
*corsivo* corsivo
- voce (a inizio riga) un elenco puntato
1. voce (a inizio riga) un elenco numerato

Due regole da ricordare:

  • Per andare a capo inserisci due spazi alla fine della riga;
  • per iniziare un nuovo paragrafo lascia una riga vuota: andare a capo una sola volta non basta;
  • prima di un elenco (e prima di un titolo) ci vuole una riga vuota, altrimenti non viene riconosciuto.

I numeri nel testo: il codice inline

Spesso nel testo di un report compaiono dei numeri: “sono stati arruolati 47.717 soggetti”. Se li scrivi a mano, il mese prossimo saranno sbagliati. Con il codice inline puoi far calcolare a R un valore direttamente dentro una frase:

  • inizia con un apice inverso (backtick), la lettera r e uno spazio;
  • scrivi il codice R;
  • chiudi con un altro apice inverso.

Per scrivere l’apice inverso:

  • Windows (tastiera italiana): prova Alt Gr + ’ (il tasto vicino a Invio, a seconda della tastiera)
  • Mac: ⌥ Option + 9 (tastiera italiana).

Per esempio, scrivi questa frase nel tuo documento e rifai il render:

Questo report è stato creato il `r Sys.Date()`.

Nel report, al posto del codice, comparirà la data di oggi. La funzione Sys.Date() restituisce la data del computer.

Prova a rispondere!

Immagina di scrivere nel documento: ‘Sono stati analizzati r nrow(dati_clean) soggetti’. Cosa comparirà nel report al posto del codice?
AvvisoAttenzione all’ordine del codice

Quarto esegue tutto dall’alto verso il basso, chunk e codice inline compresi. Se in una frase usi nrow(dati_clean), l’oggetto dati_clean deve essere stato creato in un chunk più in alto nel documento: altrimenti il render si ferma con l’errore object 'dati_clean' not found. Per questo il testo del report va scritto dopo i chunk che caricano i pacchetti e importano i dati.

Costruire il report

Ora hai tutti gli strumenti per costruire il report sulla coorte vaccinale. Cancella dal documento le prove fatte finora (calcoli, elenco, frase con la data), ma non l’intestazione YAML.

L’obiettivo di questo esercizio è creare un report descrittivo della coorte dello studio, trasformando il codice che hai scritto finora in un report automatico con Quarto. Non dovrai riscrivere il codice: ti chiederemo di copiare diversi pezzi degli script che hai fatto finora durante il corso e di incollarli nei chunk del documento Quarto. Costruirai il report un pezzo alla volta: dopo ogni pezzo, rifai il render per controllare che tutto funzioni. Se qualcosa non va, è molto più facile capire cosa è successo.

Pacchetti e dati

Il primo chunk carica i pacchetti, il secondo importa i dati. Il codice lo hai già: copialo dallo script tabelle_grouping.R. C’è, però, una differenza rispetto allo script.

  • Usa sempre here() per i percorsi dei file. Durante il render, R lavora nella cartella in cui si trova il documento Quarto (script), non nella cartella principale del progetto: un percorso come "dati/..." non verrebbe trovato. here(), invece, parte sempre dalla cartella del progetto. Quindi, invece di scrivere import("dati/dati_clean.rds"), scrivi import(here("dati", "dati_clean.rds")).

Inserisci i due chunk. Nel primo carica i pacchetti, compresi {here} e {sf}, che ti serviranno per i percorsi e per la mappa. Nel secondo importa il dataframe dati_clean.rds dalla cartella dati, chiamandolo dati_clean. Importa anche, come nel Modulo 8, lo shapefile delle regioni con read_sf(), chiamandolo regioni_sf, e la tabella regioni.rds con la popolazione, chiamandola regioni.

Clicca per leggere un suggerimento


Né il caricamento dei pacchetti né l’importazione dei dati producono qualcosa da mostrare nel report: per entrambi i chunk va bene #| include: false. Le righe per importare lo shapefile e la tabella delle regioni sono nella sezione “Mappe” dello script plot.R.

```{r}
# Caricamento pacchetti
```

ConsiglioApprofondimento: numeri più leggibili

# Descrizione della coorte

La tabella seguente riporta, per stato HIV, le principali
caratteristiche della coorte, la mediana degli anticorpi e il tasso di
diagnosi di COVID-19 per 100 anni-persona di follow-up.

```{r}
#| label: tbl-sintesi
#| tbl-cap: "Caratteristiche della coorte e diagnosi di COVID-19 per stato HIV"
sintesi_hiv <- dati_clean %>%
  group_by(hiv_status) %>%
  summarise(
    n                  = n(),
    perc_donne         = mean(sex == "F", na.rm = TRUE) * 100,
    eta_mediana        = median(age, na.rm = TRUE),
    perc_60            = mean(age >= 60, na.rm = TRUE) * 100,
    perc_charlson_3piu = mean(chrls_index == "3-4" |
                              chrls_index == "5+") * 100,
```

AvvisoAttenzione ai numeri scritti nel testo

Le frasi che introducono i grafici qui sopra contengono mesi, percentuali e regioni scritti a mano: se arrivano dati nuovi, il grafico si aggiorna ma la frase no. Nel testo, i numeri che dipendono dai dati vanno sempre scritti con il codice inline.

Un modello Word con lo stile del tuo ufficio

Quarto crea il file Word con caratteri e colori predefiniti. Se vuoi che i report abbiano lo stile del tuo ufficio (carattere, colori dei titoli, margini), puoi dare a Quarto un documento Word di riferimento da cui copiare gli stili:

  1. nel riquadro Terminal di RStudio, esegui il comando quarto pandoc -o modello.docx --print-default-data-file reference.docx: crea il file modello.docx nella cartella del progetto;
  2. apri modello.docx in Word e modifica gli stili (non il testo): per esempio, con il tasto destro su “Titolo 1” nella barra degli stili, Modifica…. Salva e chiudi;
  3. sposta modello.docx nella stessa cartella del documento Quarto e aggiungi nell’intestazione YAML, sotto docx:, la riga reference-doc: modello.docx;
  4. rifai il render.

Clicca per vedere la soluzione (provaci da solo prima!)

 


format:
  docx:
    toc: true
    number-sections: true
    reference-doc: modello.docx


Lo stesso report in HTML

Prova a creare il report anche in formato HTML. Aggiungi html ai formati nell’intestazione YAML, con queste opzioni:

  • embed-resources: true, per avere un unico file HTML (con i grafici dentro) da inviare via email;
  • code-fold: true, per mostrare il codice “piegato”: il lettore lo vede solo se clicca su Code. Perché funzioni, nel blocco execute imposta echo: true.

Per scegliere in quale formato fare il render, usa la freccia accanto al pulsante Render.

Clicca per vedere la soluzione (provaci da solo prima!)

 


format:
  docx:
    toc: true
    number-sections: true
  html:
    toc: true
    embed-resources: true
    code-fold: true
execute:
  echo: true
  warning: false

Con echo: true il codice compare anche nel report Word: per il Word conviene quindi tornare a echo: false.
